# 🛰️ Prizrak-Box на Orange Pi Zero 3W

Установка прокси-клиента **Prizrak-Box** (форк Pandora-Box на ядре mihomo) на Orange Pi Zero 3W
под Debian 13 (Trixie, MATE/X11) — с двумя неочевидными граблями этой платы: падением
графического интерфейса из-за PowerVR-обёртки и окном, которое не влезает в экран 1024×600.

**Схема работы:**
```
┌───────────────┐                    ┌──────────────────────┐              ┌───────────┐
│   Chromium    │  --proxy-server=   │  Prizrak-Box (GUI)   │   mihomo     │ интернет  │
│   Hermes      │ 127.0.0.1:9697 ──► │  ядро слушает :9697  │ ───────────► │           │
│   виджет, CLI │                    │                      │              │           │
└───────────────┘                    └──────────────────────┘              └───────────┘
```

---

## Почему так, а не иначе?

Машина перешла с другого клиента, который слушал порт **7890**. Всё окружение (браузер,
служебные скрипты, агент) было настроено на этот порт. Новый клиент поднимает своё ядро
на порту **9697** — и интернет в браузере отвалился, хотя сам клиент работал.

Что пробовали и что из этого вышло:

- **Поменять порт самого приложения** через его файл настроек — не работает: приложение
  хранит настройки в зашифрованном виде (`px-server.db` не читается как SQLite, рядом лежат
  `salt`-файлы), а `config.json` — только кэш: после перезапуска порт возвращается к 9697.
  Вывод: порт приложения — это то, что дано; под него подстраиваются остальные.
- **Вписать фикс окружения в ярлык меню** — обязательно. Без него приложение просто падает
  при запуске (в журнале остаётся аварийный дамп): на этой плате в `/usr/local/lib` лежит
  графическая обёртка PowerVR, которую движок интерфейса не переваривает. Лечится запуском
  с системным Mesa (`LD_LIBRARY_PATH=/usr/lib/aarch64-linux-gnu` + `LIBGL_ALWAYS_SOFTWARE=1`).
- **Ужать окно под экран** — не получилось. Приложение объявляет минимум **960×660**, а
  рабочая область экрана 1024×560. Снятие ограничения не помогает: приложение возвращает
  его назад, уменьшение масштаба страницы тоже не влияет. Итог: низ окна (~100 px) уходит
  за край, но кнопки и меню доступны.
- **Перекинуть порт** (проброс 7890 → 9697) — рабочий, но лишний постоянно живущий процесс.
  Выбрали вариант «привести клиентов к порту приложения»: правок столько же, но нет
  дополнительной службы, которую потом нужно сопровождать.

## Что понадобится

- Orange Pi Zero 3W (Allwinner A733), Debian 13 (Trixie), графическая сессия X11 (MATE)
- Пакет `prizrak-box` для **arm64** (сборка `linux-arm64.deb`, вариант `wails`)
- Зависимости, которые на Debian 13 обычно уже стоят: `libgtk-4-1`, `libwebkitgtk-6.0-4`
- `xdotool`, `xprop`, `scrot` (для запуска-обёртки и скриншотов)
- Python 3 с `python3-xlib` (для снятия ограничения размера окна)

## Часть 1. Установка

Скачиваем deb-пакет arm64 и **сверяем контрольную сумму** с официальной (GitHub отдаёт
sha256 в описании релиза):

```bash
# имя файла и сумма берутся со страницы релиза
curl -L -o prizrak-box.deb \
  "https://github.com/legiz-ru/Prizrak-Box/releases/download/<ТЕГ>/linux-arm64-wails.deb"
sha256sum prizrak-box.deb        # сравнить с digest из релиза!

sudo apt install -y ./prizrak-box.deb
dpkg-query -W -f='${Package} ${Version} ${Architecture}\n' prizrak-box
```

**Параметры:**
- сборка `wails` — на ~половину легче основной (60 против 130 МБ) и собрана под GTK4/WebKitGTK 6.0,
  которые есть в Debian 13; старые сборки требуют библиотек, которых в Trixie уже нет
- `apt install ./файл` вместо `dpkg -i` — чтобы сразу подтянулись зависимости

Проверка, что установилось:

```bash
ls -l /usr/bin/prizrak-box                       # символическая ссылка на /usr/lib/prizrak-box/...
ls /usr/share/applications/ | grep prizrak       # ярлык в меню
```

## Часть 2. Запуск из меню (фикс PowerVR)

Симптом: из меню приложение не открывается, хотя права и зависимости в порядке.

Причина: на плате PowerVR-обёртка `libEGL` из `/usr/local/lib` подхватывается раньше системной,
а движок интерфейса её не принимает — приложение падает.

Лечение — запускать через скрипт-обёртку `scripts/prizrak-launch.sh`, который выставляет
окружение и подгоняет окно. Ярлык в меню переключаем на этот скрипт:

```bash
cp scripts/prizrak-launch.sh ~/prizrak-launch.sh
cp scripts/win-fit.py ~/win-fit.py
chmod +x ~/prizrak-launch.sh ~/win-fit.py

# ярлык в меню → на скрипт (путь подставьте свой)
sudo sed -i 's|^Exec=.*|Exec='"$HOME"'/prizrak-launch.sh %u|' \
  /usr/share/applications/prizrak-box.desktop
grep '^Exec' /usr/share/applications/prizrak-box.desktop
```

Проверка, что падение вылечено — в журнале запуска не должно быть дампа регистров:

```bash
~/prizrak-launch.sh; sleep 25
pgrep -c -f /usr/bin/prizrak-box                  # > 0
grep -c libEGL /proc/$(pgrep -f /usr/bin/prizrak-box | head -1)/maps   # путь Mesa, не /usr/local
```

## Часть 3. Окно на экране 1024×600

Приложение требует **минимум 960×660**, экран платы — 1024×600, рабочая область под панелью —
1024×560. Ужать окно нельзя: попытка снять ограничение не держится (приложение возвращает
свой минимум), масштаб страницы на это не влияет.

Практический итог: окно 1024×660 встаёт в точку 0,40, нижняя полоса ~100 px уходит за край —
там только подпись под кнопками, сами кнопки и левое меню доступны.

Если нужно видеть окно целиком, единственный честный путь — виртуальный экран выше физического
(панорамирование), например:

```bash
xrandr --fb 1024x700 --panning 1024x700     # картинка сдвигается к краям экрана
xrandr --fb 1024x600                        # вернуть как было
```

## Часть 4. Подписка

Профиль добавляется в интерфейсе приложения (кнопка «+» на главном экране). Данные профиля
хранятся в домашнем каталоге приложения и в общий доступ не попадают.

Если переносите профиль с другого клиента, **сначала сделайте копию его каталога данных** —
это единственный источник, из которого потом можно восстановить подписку:

```bash
cp -a ~/.local/share/<каталог-старого-клиента> ~/backup-<дата>/
```

## Часть 5. Свод портов

Клиенты обычно жёстко прописаны в ярлыках и службах. Чтобы всё ходило через порт приложения
(в примере — 9697), правим **все** места разом; готовый скрипт — `scripts/align-proxy-port.sh`
(старый порт и новый — константы в начале файла).

Места, которые надо проверить:

```bash
grep -rIl "127.0.0.1:7890" ~/.hermes ~/.config ~/.local/bin ~/*.py ~/Desktop 2>/dev/null
```

- **ярлык браузера** — флаг `--proxy-server=http://127.0.0.1:9697`
- **настройки агента** (если поднят Hermes) — у него прокси задаётся отдельной надстройкой
  над службой: `~/.config/systemd/user/hermes-gateway.service.d/proxy.conf`
- **виджеты и скрипты**, которые сами запускают браузер, — у них порт прописан константой
- после правки — перезапуск службы (агента) и **перезапуск браузера**: уже запущенное окно
  держит старый порт в памяти

Проверка:

```bash
ss -tln | grep -E ':(9697|7890)'                                  # слушается только 9697
curl -s -o /dev/null -w '%{http_code}\n' -x http://127.0.0.1:9697 https://www.youtube.com
```

## Часть 6. Переход с другого клиента

Порядок, который не оставляет машину без связи:

1. **Копия профиля** старого клиента (см. Часть 4) и, если есть, его deb-пакета для откатa.
2. Установка и настройка нового клиента (Части 1–5).
3. Остановка старого клиента и **удаление** его пакета, автозапуска и своих скриптов запуска.
4. Проверка, что старых файлов не осталось, и что порт прокси слушается:

```bash
for p in /usr/bin/<старый-клиент> /opt/<старый-клиент> /usr/share/<старый-клиент>; do
  [ -e "$p" ] && echo "осталось: $p"
done
dpkg-query -W -f='${Package} ${Version}\n' <старый-пакет> 2>/dev/null || echo "пакет удалён"
ss -tln | grep :9697
```

## Часть 7. Проброс порта (если приложения менять не хочется)

Если потребителей много — или среди них есть приложения, которые **не видят переменные
окружения хоста** (Flatpak, Snap), — вместо правки каждого можно один раз пробросить старый
порт на новый. Готовый проброс — `scripts/port-forward.py` (порты — константы в начале файла),
юнит для автозапуска — `systemd/prizrak-port-forward.service`.

Установка службой пользователя (поднимается вместе с графической сессией):

```bash
cp scripts/port-forward.py ~/port-forward.py
mkdir -p ~/.config/systemd/user
cp systemd/prizrak-port-forward.service ~/.config/systemd/user/

systemctl --user daemon-reload
systemctl --user enable --now prizrak-port-forward.service
systemctl --user status prizrak-port-forward.service --no-pager | head -5
```

**Проверка** — слушаются оба порта, и через любой из них есть выход:

```bash
ss -tln | grep -E ':(7890|9697)'
curl -s -o /dev/null -w '%{http_code}\n' -x http://127.0.0.1:7890 https://api.telegram.org
curl -s -o /dev/null -w '%{http_code}\n' -x http://127.0.0.1:9697 https://www.youtube.com
```

**Особый случай — Telegram Desktop (Flatpak)**: разрешение `shared=network` у него есть
(то есть `127.0.0.1` хоста ему виден), но **своего прокси он не знает** и ходит напрямую —
а напрямую Telegram из многих сетей недоступен, поэтому «не работает». Настраивается в самом
приложении: *Настройки → Продвинутые настройки → Тип соединения → Использовать прокси →
SOCKS5, сервер `127.0.0.1`, порт 7890 (или 9697 — после проброса работают оба)*. Правки
файлов тут не помогут: настройки приложения хранятся в его собственном формате и привязаны
к аккаунту.

### Обязательно: снимать таймаут у сокетов проброса

Грабля, которая стоила часа разбирательств. У долгих соединений (Telegram long-poll,
WebSocket, стримы) бывают паузы в десятки секунд. Если у сокета остаётся рабочий таймаут,
проброс **рвёт такие потоки на первой же паузе** — приложения видят `UND_ERR_SOCKET`
и уходят в цикл «соединение упало → пауза 60 с → переподключение», хотя короткие запросы
проходят нормально и потому ничего не подозрительно.

Причина: `socket.create_connection(addr, timeout=...)` ставит таймаут **и на обмен данными**
тоже, а не только на подключение. Лечение:

```python
upstream = socket.create_connection((host, port), timeout=15)   # таймаут подключения
upstream.settimeout(None)                                        # снять для обмена
client.settimeout(None)
```

**Проверка именно этой грабли** — короткие запросы её не показывают, нужен простой:

```bash
# ставим соединение, ждём 30 секунд, потом отправляем запрос
( sleep 30; printf 'GET / HTTP/1.1\r\nHost: api.telegram.org\r\nConnection: close\r\n\r\n' ) | \
  timeout 55 openssl s_client -proxy 127.0.0.1:7890 -connect api.telegram.org:443 -quiet | head -1
# ожидаем строку статуса (302 у Telegram); «обрыв» = таймаут не снят
```

## Часть 8. Автозапуск после перезагрузки

У приложения нет собственного автозапуска, поэтому после включения машины прокси не поднимается
сам. Запись автозапуска сессии — `autostart/prizrak-box.desktop`; она ведёт на скрипт-обёртку
из Части 2, поэтому при старте сразу применяются и фикс рендера, и подгонка окна.

```bash
mkdir -p ~/.config/autostart
cp autostart/prizrak-box.desktop ~/.config/autostart/
sed -i "s|<ваш-домашний-каталог>|$HOME|" ~/.config/autostart/prizrak-box.desktop
grep '^Exec' ~/.config/autostart/prizrak-box.desktop
```

**Параметры:**
- `X-MATE-Autostart-Delay=20` — пауза перед запуском, чтобы сессия успела поднять панель и трей
- `X-MATE-Autostart-enabled=true` — без этой строки MATE считает запись выключенной

Проверка (имитация перезагрузки: полностью гасим приложение и запускаем ровно той командой,
что записана в автозапуске):

```bash
pkill -f /usr/bin/<клиент>; sleep 8
setsid nohup $(grep '^Exec=' ~/.config/autostart/prizrak-box.desktop | cut -d= -f2) &
sleep 50
ss -tln | grep -E ':(9697|7890)'                       # ядро и проброс
curl -s -o /dev/null -w '%{http_code}\n' -x http://127.0.0.1:9697 https://api.telegram.org
```

Если автозапуск не сработал после реальной перезагрузки, смотрите журнал сессии:

```bash
grep -i prizrak ~/.xsession-errors
journalctl --user --since "10 min ago" | grep -i prizrak
```

## Часть 9. Раздельная маршрутизация: модель напрямую, остальное через ВПН

Бывает нужно, чтобы один сервис шёл **мимо** ВПН, а всё остальное — через него. Живой пример:
DeepSeek в РФ не заблокирован, но через VPN-узлы отвечает нестабильно — при плохом узле агент
на этой машине «замолкает» с ошибкой `API call failed ... Connection error`, хотя Telegram и
YouTube при этом работают. Лечится одной строкой правила в ядре клиента:

```
DOMAIN-SUFFIX,deepseek.com,DIRECT
```

Режим tun выключать не нужно и бессмысленно: mihomo применяет свои правила к любому трафику,
который через него идёт, — и в туннеле, и в режиме прокси. Зато **без** tun хуже: в прокси
попадут только программы, знающие про системный прокси, а остальные уйдут напрямую целиком,
и у них отвалятся Telegram и YouTube.

### Как устроено

- Ядро клиента — mihomo, управление слушает `127.0.0.1:9686`, ключ лежит в базе клиента
  (`~/Prizrak-Box-V3/px-server.db`, поле вида `Rule_No1SecretKey_pb"<ключ>"`). Запрос без ключа
  отдаёт `401 Unauthorized`.
- Конфиг ядра клиент собирает из активного профиля (подписка) и шаблона правил. Профиль
  перезаписывается при обновлении подписки, встроенные шаблоны (`Template_0..2`) — при обновлении
  версии приложения. Поэтому правка файлов «в лоб» недолговечна: нужен либо свой шаблон, либо
  повторное применение.
- Конфиг применяется **атомарно**: `PUT /configs?force=true` с путём к файлу. При ошибке ядро
  оставляет прежний конфиг, связь не рвётся. Файл обязан лежать внутри каталога клиента
  (`~/Prizrak-Box-V3`), иначе ответ `400 path is not subpath of home directory or SAFE_PATHS`.

### Применение

```bash
python3 scripts/pbfix-deepseek.py --check    # посмотреть правила, которые держит ядро
python3 scripts/pbfix-deepseek.py            # собрать конфиг с правилом и применить
```

Скрипт собирает полный конфиг (основа — шаблон: tun, dns, sniffer; сверху — прокси и группы из
активного профиля; tun — из текущего состояния ядра), ставит правило **первым**, перезагружает
ядро и возвращает ранее выбранную ноду. Если правило уже на месте — ничего не меняет, поэтому
его можно смело запускать по таймеру. Ключ управления скрипт берёт из базы клиента сам
(или из переменной `PB_SECRET`).

### Проверка

```bash
# правила в ядре
curl -s -H "Authorization: Bearer <ключ>" http://127.0.0.1:9686/rules | grep -o '"payload":"[^"]*"'

# решения ядра по живым запросам
curl -s -o /dev/null https://api.deepseek.com/
curl -s -o /dev/null https://api.telegram.org/
tail -5 ~/Prizrak-Box-V3/logs/px-server.log | grep -E "deepseek|telegram"
```

Ожидаемо: `api.deepseek.com:443 match DomainSuffix(deepseek.com) using DIRECT` и при этом
`api.telegram.org:443 match Match using → <группа ВПН>[<нода>]`.

### Сторож: правило не теряется

Служба и таймер из `systemd/` раз в 5 минут проверяют, есть ли правило в ядре. Есть — молчат;
исчезло (например клиент пересобрал конфиг после обновления подписки) — восстановят.

```bash
mkdir -p ~/.config/systemd/user
cp systemd/pbfix-deepseek.service systemd/pbfix-deepseek.timer ~/.config/systemd/user/
systemctl --user daemon-reload
systemctl --user enable --now pbfix-deepseek.timer

systemctl --user list-timers pbfix-deepseek.timer     # когда следующий запуск
journalctl --user -u pbfix-deepseek -n 5              # что делал
```

Работает и без входа в систему, если у пользователя включён `Linger`
(`loginctl enable-linger <пользователь>`).

### Долговременная альтернатива без сторожа

Выбрать в интерфейсе клиента **свой** шаблон правил с этой строкой. Важно: встроенные шаблоны
приложение перезаписывает при обновлении своей версии, поэтому нужен именно пользовательский
шаблон. Учтите, что вместе с ним применятся все правила шаблона — блокировка рекламы, списки
недоступных сайтов, правила для Discord и так далее.

## Частые проблемы

| Проблема | Решение |
|---|---|
| Из меню приложение не запускается, в журнале дамп регистров | Запускать через скрипт с `LD_LIBRARY_PATH=/usr/lib/aarch64-linux-gnu` и `LIBGL_ALWAYS_SOFTWARE=1` (Часть 2) |
| Окно не уменьшается, низ уезжает за край | Минимум 960×660 задан приложением; см. Часть 3 (смириться или виртуальный экран) |
| Браузер без интернета после смены клиента | Порт в ярлыке браузера указывает на старый клиент; свести порты (Часть 5) и **перезапустить браузер** |
| `pkill -f "клиент"` убивает саму команду | Шаблон в `pkill -f` совпадает с собственной строкой запуска — выносить убийство в отдельный файл-скрипт |
| Порт приложения не меняется правкой файла настроек | Настройки в зашифрованном виде; менять порт только в интерфейсе приложения |
| После перезагрузки прокси не поднялся | У приложения нет автозапуска — добавить ярлык в автозапуск сессии, ведущий на скрипт-обёртку |
| Flatpak-приложение (напр. Telegram Desktop) не подключается | Оно не видит переменные окружения хоста: указать прокси в настройках самого приложения (SOCKS5 `127.0.0.1:7890`) или включить проброс порта (Часть 7) |
| Приложение постоянно теряет связь (`UND_ERR_SOCKET`, сокет «упал»), хотя короткие запросы проходят | У сокетов проброса не снят таймаут обмена — длинные паузы рвут соединение (Часть 7, «снимать таймаут») |
| Модель «молчит», хотя Telegram и YouTube работают | Трафик к ней идёт через VPN-узел: вывести адрес напрямую (Часть 9) |
| После обновления подписки правило «напрямую» исчезло | Клиент пересобрал конфиг ядра — вернуть сторожем или своим шаблоном (Часть 9) |

## Альтернативы

- **FlClashX** (`github.com/pluralplay/FlClashX`) — тоже GUI поверх mihomo; на этой плате нужен
  свой фикс: setuid на ядро и запуск через системный Mesa (см. репозиторий `opi-zero3w-flclashx-debian13`).
- **mihomo без GUI** (`orangepi-zero3w-mihomo-setup`) — минимум зависимостей, но настройка через
  конфиг-файл, без окна.
- **Проброс порта** (7890 → 9697) — если менять настройки клиентов нельзя или их слишком много.
